Project: TeachTales - QTI 3.0 & OneRoster 1.1 Integration with Existing UI

OVERALL DESCRIPTION:
TeachTales integrates QTI 3.0 assessment standards and OneRoster 1.1 user management into the already-built frontend UI. The system transforms AI-generated stories into QTI assessment packages with adaptive section unlocking, while managing users and progress through OneRoster standards. All UI screens are complete and functional - this project focuses on connecting them to the standards-based API running on localhost:8080.

AI STORY GENERATION AGENT:

Purpose: Generate educational stories with integrated comprehension questions
Technology: Google Gemini Pro API
Input Structure:
```json
{
  "universe": "Pokemon",
  "character": "Luigi",
  "spark": "A mysterious egg appears",
  "gradeLevel": "4th Grade",
  "previousChapter": null, // or summary if continuing
  "selectedPath": null // or chosen path if continuing
}
```

Prompt Template:
"Generate a children's story chapter with these requirements:
1. Universe: {universe}, Main Character: {character}
2. Story premise: {spark} [or continue from: {previousChapter} following path: {selectedPath}]
3. Reading level: {gradeLevel}
4. Structure: Exactly 5 sections, approximately 150 words each
5. Questions: 4 comprehension questions, one per section (not for section 5)
6. Return as JSON with title, sections array, and questions array"

Output Transformation to QTI:
- Each section becomes QTI assessmentSection with unique identifier
- Questions become QTI assessmentItems with choiceInteraction
- Correct answers stored in responseDeclaration
- Section unlocking via branchRule conditions

MULTI-CHAPTER STORY FLOW:

1. First Chapter:
   - Generated from universe + character + spark
   - Establishes story setting and conflict
   - Ends with choice for next direction

2. Subsequent Chapters:
   - AI Agent receives previous chapter context
   - Maintains character development and plot continuity
   - Selected path influences story direction
   - Each chapter ends with new choices

3. Story Continuity Management:
   - Store chapter summaries in database
   - Pass context to AI for coherent narrative
   - Track story arc in QTI metadata
   - Maximum 10 chapters per book (configurable)

ONEROSTER RELATIONSHIPS:

Parent-Child Relationship via Agents:
- Parent User:
  ```json
  {
    "sourcedId": "parent-123",
    "role": "parent",
    "agents": [
      {"sourcedId": "child-456", "type": "student"},
      {"sourcedId": "child-789", "type": "student"}
    ]
  }
  ```
- Child User:
  ```json
  {
    "sourcedId": "child-456",
    "role": "student",
    "agents": [
      {"sourcedId": "parent-123", "type": "parent"}
    ]
  }
  ```

Student-Class Relationship via Enrollments:
- Enrollment connects student to class (book)
- NOT used for parent-child relationships
- Used for tracking which books a child is reading

QTI 3.0 ASSESSMENT STRUCTURE:
```xml
<assessmentTest>
  <testPart>
    <assessmentSection identifier="section-1">
      <assessmentItemRef identifier="question-1"/>
      <branchRule target="section-2">
        <correct identifier="question-1"/>
      </branchRule>
    </assessmentSection>
    <!-- Sections 2-5 with similar structure -->
  </testPart>
</assessmentTest>
```

STATE MANAGEMENT:
- Store current QTI assessment in React context
- Track unlocked sections in component state
- Cache OneRoster data to minimize API calls
- Persist reading progress to API on each answer
- Maintain story context for multi-chapter books

ERROR HANDLING:
- Network failures: Show retry button, preserve user input
- Invalid QTI: Fallback to basic display mode
- OneRoster sync issues: Queue updates for later
- Auth expiry: Redirect to login with return URL
- AI generation failures: Retry with exponential backoff
