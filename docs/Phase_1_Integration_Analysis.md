# Phase 1 Integration Analysis

## Current Question Generation Flow Analysis

### Flow Diagram
```
StoryGenerationRequest → PromptTemplates.generateStoryPrompt() → 
GeminiClient → JSON Response → PromptTemplates.parseAIResponse() → 
StoryGenerationResponse → StorySection.questions: ComprehensionQuestion[] →
StoryStorageService.saveStory() → AssessmentService.createStoryAssessments()
```

### Key Integration Points Identified

#### 1. ComprehensionQuestion Structure (ai/types.ts:38-51)
**Current Definition:**
```typescript
export interface ComprehensionQuestion {
  id: string;
  type: 'multiple_choice' | 'true_false' | 'short_answer';
  question: string;
  options?: string[];
  correct: number | string;
  explanation: string;
}
```

**Usage Context:**
- Generated by AI via `PromptTemplates.generateStoryPrompt()` 
- Each section gets exactly 2 questions (1 literal, 1 inferential)
- Stored in `StorySection.questions: ComprehensionQuestion[]`
- Converted to QTI assessments by `AssessmentService.createStoryAssessments()`

**Integration Opportunity:** This is our **primary extension point** - we can extend this interface without breaking existing functionality.

#### 2. StorySection Structure (ai/types.ts:58-66)
**Current Definition:**
```typescript
export interface StorySection {
  id: number;
  content: string;
  questions: ComprehensionQuestion[];
}
```

**Integration Impact:** Our enhanced questions must remain compatible with `ComprehensionQuestion[]` to preserve existing storage and retrieval workflows.

#### 3. ValidationResult Patterns

**Current AI Types ValidationResult (ai/types.ts:119-123):**
```typescript
export interface ValidationResult {
  isValid: boolean;
  errors: string[];
  warnings: string[];
}
```

**QTI Validator ValidationResult (qti/validators/qti-validator.ts:21-26):**
```typescript
export interface ValidationResult {
  valid: boolean;
  errors: ValidationError[];
  warnings: ValidationWarning[];
  summary: ValidationSummary;
}
```

**Integration Challenge:** Two different `ValidationResult` interfaces exist. We need to choose one pattern and extend it consistently.

#### 4. Story Storage Integration (services/story-storage-service.ts)

**Current Flow:**
- `StoryStorageService.saveStory()` separates questions from sections
- Questions stored as separate assessments via `AssessmentService`
- Sections stored without questions in stimulus content
- Questions reconstructed on retrieval

**Integration Impact:** Our enhanced validation must work with this separation/reconstruction flow.

## Validation Pattern Integration

### Recommendation: Use QTI ValidationError Pattern
The QTI validators use a more sophisticated error structure:

```typescript
export interface ValidationError {
  type: ValidationErrorType;
  message: string;
  line?: number;
  column?: number;
  element?: string;
  suggestion?: string;
  severity: 'error' | 'warning' | 'info';
  questionId?: string;  // Our addition for question-specific errors
}
```

This provides better error reporting than the simple `string[]` errors in ai/types.ts.
